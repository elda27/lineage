# 画面構成

## minos
minosは瞬時に起動し、ユーザの入力を受け付けることができる軽量なデスクトップアプリケーションです。
アプリケーションはgpuiで実装され、閉じるボタンを押してもタスクトレイに常駐し、Alt+Spaceで呼び出すことができる。minosの入力画面ではAlt+Fでfullosを起動できる。ユーザの入力は、minosのデータとして格納される。
タスクトレイから右クリックでfullosの起動やminosの終了を行うことができる。fullosの起動は入力画面のボタンからも行える。
ただし常駐するのはユーザが閉じたときだけで、Windowsのシャットダウン/ログオフや、インストーラ（Restart Manager）からの終了要求には従って終了する。トレイに残り続けるとインストーラがminosを更新できず、トレイアイコンを失ったプロセスだけが残ってしまう。

インストーラはminosをログオン時とインストール完了時に自動起動する（[docs/release.md](release.md#minos-の自動起動)）。自動起動のときは`--autostart`が付き、入力画面を出さずトレイに入るだけになる。ユーザ自身がショートカットから起動したときだけ入力画面が開く。すでに常駐している状態で`--autostart`付きの起動が重なった場合は、既存のウィンドウを出さずに黙って終了する。

Windows 11 は初めて見るトレイアイコンをオーバーフロー（`^`）に隠すため、初回だけ通知領域に表示されるよう設定する（[minos/src/infra/system/tray_promotion.rs](../minos/src/infra/system/tray_promotion.rs)）。昇格を要求する API は無く、Windows の表示設定 `HKCU\Control Panel\NotifyIconSettings\<hash>\IsPromoted` を直接書く非公開の手段しかない。設定済みの場合は触らないので、ユーザが「隠す」を選んだらその選択が残る。反映は Windows が設定を読み直してからなので、初回起動時ではなく次の起動から見えるようになる。

1. Alt+Spaceで呼び出すことができる。画面はテキストボックス1つと送信ボタン1つを有する。送信ボタンのクリックまた、Ctrl+Enterで送信することができる。Ctrl+Shift+Enterで送信した場合はウィンドウを閉じず、直前のアプリ情報を引き継いで続けて入力できる。
   - 画面中央に表示される
   - 最前面に表示される（最前面固定ではない）
   - 直前にForegroundのアプリのテキストをそのままテキストボックスにコピーすることができる。コピーしたテキストは、minosのデータとして格納される。
   - 「fullos を開く」ボタンでfullosを起動できる。起動できたらminosはタスクトレイに戻り、入力中の内容はそのまま残る。fullosが見つからないときはその旨を画面に表示する。
2. `#`キーを押すとメタ情報を追加ですることが出来る。メタ情報は自動追加する情報と、ユーザが任意に追加する情報の2種類がある。自動追加する情報の一つとして、直前に開いていたアプリケーションの情報を追加する。ユーザが追加するメタ情報は入力補完を行い、より短期間での入力を可能にする。メタ情報の入力補完は、ユーザが過去に入力したメタ情報を学習して行う。学習した情報はfullosで詳細な設定を行え、短縮文字列を定義することができる。例えば`#タスク`の短縮文字に`task`を設定すると`#t`と入力するだけで、補完候補として`#タスク`が表示されるようになる。`t`から始まる文字が複数あっても、`#ta`と続く文字列を入力売ることでさらに候補を絞り込むことができる。
3. 入力が完了したら、データを格納する。

## agentos
agentosは、ユーザの操作を自動化するためのアプリケーションです。ユーザが登録したデータに基づき、ユーザの操作を自動化することができる。Agentや、ユーザが登録したルールに基づく操作の自動化を行うことができる。

agentosはRustのCUIとして実装され、常駐せず状態も持たない。DBとコマンド引数とOSの資格情報ストアだけで動くので、タスクスケジューラからでもfullosからでもシェルからでも、同じように1回ぶんの実行として呼べる。画面は持たない（UIはfullosが持つ）。

```
agentos run    --rule <id> --memo <id>   ルールを1件、指定の記録に対して実行する
agentos match  --memo <id>               その記録に当てられるルールを一覧する
agentos render --rule <id> --memo <id>   送るプロンプトを組み立てて出力する
agentos record --rule <id> --memo <id> --result-file <path|->
                                         外部で得た結果を確定する
agentos poll                             メタ情報マッチの未処理分をまとめて実行する
agentos schedule-due                     発火時刻が来たスケジュールを実行する
agentos tick                             定期起動からの1回ぶん（poll + schedule-due）
agentos rules / verify                   ルール一覧 / hash-chain の検証
agentos credential set|has|delete --provider <name>
                                         APIキーをOSの資格情報ストアで扱う
```

定期実行が必要なルール（メタ情報マッチ・スケジュール）は、fullosの設定画面から`agentos tick`をタスクスケジューラに登録して動かす。常駐プロセスを増やさないための構成であり、登録は利用者が明示的に有効にしたときだけ行う。

`links`への追記（結果documentと元の記録を`derived_from`でつなぐ処理）は、minosとagentosが共有する`lineage-core`クレート1本に集約している。fullosはこの鎖に直接書かない。


## fullos
fullosはminosのビューおよび設定を行うアプリケーションである。
fullosはtauriで実装され、ユーザの操作を自動化するためのAgentや、ユーザが登録したルールに基づく操作の自動化を行うことができる。
トップ画面に検索バーとダッシュボードを備え、サイドバーから他の機能にアクセスできる。ダッシュボードは、ユーザが登録したデータの一覧やユーザカスタマイズによるルールに基づくデータ表示を行う。ルールに基づくデータ表示とは、タスク一覧の表示や、特定のメタ情報を持つデータの一覧表示などである。
トップ画面以外の機能として以下の画面を備える。

1. 検索画面
   - 検索バーに入力した文字列に基づき、ユーザが登録したデータの一覧を表示する。
   - トップ画面に備えた検索バーは本画面の簡易機能を想定しており、より高度な検索は本画面で行うことができる。
   - 検索結果の一覧から、データの詳細画面に遷移することができる。
2. データ詳細画面
   - データの詳細情報を表示する。
   - データの編集や削除を行うことができる。
3. 自動化画面
    - ユーザが登録したデータに基づき、ユーザの操作を自動化することができる。
    - Agentや、ユーザが登録したルールに基づく操作の自動化を行うことができる。
    - Agentの編集動作は
4. 設定画面
   - ユーザの設定を行うことができる。
   - ユーザの設定は、minosの動作やfullosの表示に影響する。
5. エージェントskillの配置
   - 起動時に、利用者が使っているエージェントCLIへlineageの手順書（skill）を配置するか確認する。


### 組み込みタグ
メタ情報のうちいくつかは「組み込みタグ」として扱う。付けるとfullos側の機能が有効になることが約束されたタグで、利用者が自由に付ける他のメタ情報とは違い、アプリが意味を知っている。

組み込みタグの付いた記録は一覧で優先的に表示される。どのラベルがどの組み込みタグかは表記ゆれを含めて[fullos/core/domain/memo/BuiltinTag.ts](../fullos/core/domain/memo/BuiltinTag.ts)の1か所で定義し、画面ごとに判定を持たない。

1. **`#タスク`**（`task` / `todo`）
   - 一覧で優先的に表示される。
   - 完了フラグとしてチェックボタンが出る。
   - チェックしたままfullosを閉じるとアーカイブ状態になり、一覧に出なくなる。検索すれば見つかる。
   - チェックした瞬間ではなく閉じるときにまとめてアーカイブするのは、開いている間は押し間違いを取り消せるようにするため。
2. **`#メモ`**（`memo`）
   - 一覧で優先的に表示される。
   - ゴミ箱ボタンとアーカイブボタンが出て、削除かアーカイブをその場で行える。

アーカイブは記録を消さない。一覧から外れるだけで、検索画面でキーワードやメタ情報を入れれば結果に出る（「アーカイブ」の絞り込みからも辿れる）。ゴミ箱は一覧にも検索結果にも出さないが、これも論理削除であって`documents`の行は残す。`links`が指す先を消すとhash-chainの辿れないlinkができるためで、ゴミ箱に入れた記録は自動化の定期実行の対象からも外れる。

状態（完了・アーカイブ・ゴミ箱）は`document_states`テーブルに持ち、利用者が打ったメタ情報（`document_meta`）とは混ぜない。操作の結果であってタグではないので、補完候補の学習にも検索にも出さない。

### 検索画面
検索画面は上段に検索バー、下段に検索結果のファイル一覧を備える。
メタ情報の検索は、テキスト入力によるインテントの他に、`#`キーを押すことで、登録されたメタ情報を補完することができる。

生成AIを用いてユーザの入力に基づく、RAGやエージェント操作を行うこともできる。

### 自動化画面
ユーザが登録したデータに基づき、ユーザの操作を自動化することができる。Agentや、ユーザが登録したルールに基づく操作の自動化を行うことができる。

例えばメモのメタ情報に基づいて、作業を自動化することを意図している。

自動化ルールは「プロンプト」「実行方法」「きっかけ」の3つで決まる。

1. **プロンプト** — 生成AIに渡す指示。`{{memo.title}}` `{{memo.body}}` `{{memo.metas}}` `{{now}}` を差し込める。差し込みが無いものは定型の指示になる。式や条件分岐は持たない。
2. **実行方法** — 2種類ある。
   - **APIキー** … 設定画面で登録した鍵で提供元のHTTP APIを直接呼ぶ。鍵はOSの資格情報ストアに入り、DBにも画面にも平文では現れない。
   - **ブラウザ** … 提供元のWeb画面をアプリ内の別WebViewで開き、プロンプトを入力欄に流し込んで応答をDOMから読み取る。初回はログインを手で行う。第三者のページを開くのでIPCは一切与えず、結果はウィンドウタイトル経由で受け取る。セレクタは設定画面から直せる（先方の改修で必ず壊れるため）。なお多くのサービスは自動操作を利用規約で禁じており、利用は自己責任になる。
3. **きっかけ** — 手動 / メタ情報マッチ / スケジュール。手動でも、記録の隣の「Action」ボタンから条件に合うルールを候補として出して実行できる。

実行結果は`documents`に`document_type = 'automation_result'`として保存され、元の記録から`derived_from`のlinkで辿れる。つまり自動生成物も「何から作られたか」がhash-chainに載る。同じ記録を二重に処理しないよう、成功済み・実行中のものは次回の対象から外れる。失敗したものは次回また拾われる（鍵の未登録や通信断は時間をおけば直るため）。

### エージェントskillの配置
Codex CLI / GitHub Copilot CLI / Gemini CLI / Claude Code は、いずれもホーム直下の設定ディレクトリに置かれた`SKILL.md`を読む。fullosはそこへlineageの手順書（`agentos`の使い方と、台帳を壊さないための決まり）を配置する。エージェントに毎回CUIの使い方を説明させずに済み、`links`へ直接書くような壊し方も先回りして禁じられる。

| エージェント | 配置先（ホームからの相対） |
| --- | --- |
| Codex CLI | `.codex/skills/lineage/` |
| GitHub Copilot CLI | `.copilot/skills/lineage/` |
| Gemini CLI | `.gemini/skills/lineage/` |
| Claude Code | `.claude/skills/lineage/` |

配置するのは`SKILL.md`（本文）と`version.json`（版）の2つ。`agentos`の場所は環境ごとに違うため、判明している絶対パスを本文に埋め込んでから書き込む。

起動時の動作は「追加」と「更新」で分かれる。

- **追加** … エージェントCLIが入っていて、まだskillが無い場合。確認ダイアログを出し、対象をチェックボックスで選ばせる。「今後この確認を表示しない」にチェックを付けると、以後ダイアログは出ない（設定は`settings`テーブルの`agent_skill.prompt`）。エージェントCLIが見つからないものには何も置かない。使っていないツールの設定ディレクトリが勝手に増えるのは、利用者から見て説明のつかない変化になるため。
- **更新** … 既にskillがあり、`version.json`の版が配布する版より古い場合。確認せずに入れ替える。置くことへの同意は既に得られており、古い手順書が残り続けるほうが害になる。「今後表示しない」を選んでいても更新は続く。

版はアプリのVERSIONとは別に持つ（`core/domain/skill/LineageSkill.ts`の`LINEAGE_SKILL_VERSION`）。skillの中身はアプリの更新とは無関係に変わるため、同じ番号にすると「アプリを上げただけで配り直す」ことになる。本文を変えたときは必ずこの値を上げる。

ダイアログを止めたあとの入口として、設定画面に同じ操作（配置状況の一覧・個別の追加・確認を出すかの切り替え）を置く。

ファイルの書き込みはRust側（`fullos/src-tauri/src/skill.rs`）で行う。webviewから渡る相対パスの要素は、`..`・区切り文字・`:`を含むものをRust側で弾く。検査をwebview側に置くと、そこを通さない呼び出しで抜けられるため。
